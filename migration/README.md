# ProStock Migration Blueprint

> Complete documentation for rebuilding ProStock as a native Base44 application while preserving all existing data.

## Contents

| File | Description |
|------|-------------|
| `SCHEMA.md` | Complete entity schemas for all 10 Firestore collections, field types, defaults, and relationships |
| `BUSINESS_LOGIC.md` | All calculations, workflows, stock deduction logic, and data integrity rules with pseudocode |
| `PAGES_AND_ROLES.md` | All 10 pages, their components, data dependencies, user workflows, and role-based access control |
| `exports/` | JSON and CSV exports of all Firestore data (generated by the export script) |

## Export Instructions

The export script reads all Firestore data using the Firebase Admin SDK with the `FIREBASE_SERVICE_ACCOUNT_KEY` environment variable.

```bash
# From the sandbox, run inside the web container:
docker compose -f docker-compose.base44.yml exec -T web node /tmp/export-firestore.js
```

This produces:
- `migration/exports/<collection>.json` — Full fidelity JSON for every collection
- `migration/exports/<collection>.csv` — CSV for flat collections (categories, stations, staff, taxes, subcategories, users)

### Key Relationships

```
items ──→ categories (categoryId)
items ──→ subcategories (subcategoryId, optional)
items ──→ stations (stationId, optional)
items ──→ items (components[].itemId — self-referencing for composite recipes)
items ──→ taxes (taxIds[] — multiple tax references)
sales ──→ items (items[].itemId — each sale line item references an item)
sales ──→ users (userId — who processed the sale)
wasteEvents ──→ items (itemId)
wasteEvents ──→ users (userId)
stockReceipts ──→ items (itemId)
stockReceipts ──→ users (userId)
users ──→ (self-managed via Firebase Auth + Firestore users collection)
staff ──→ (standalone, referenced by name in waste/receipt forms)
```

## Migration Strategy for Native Base44

1. **Create Base44 entities** matching the schemas in `SCHEMA.md`
2. **Import data** from the JSON exports in `exports/` using Base44's data import tools
3. **Recreate business logic** using Base44's formula/action system per `BUSINESS_LOGIC.md`
4. **Rebuild pages** using Base44's page builder per `PAGES_AND_ROLES.md`
5. **Configure roles & permissions** per the role definitions in `PAGES_AND_ROLES.md`
6. **Verify data integrity** by comparing item counts, stock values, and key records between old and new apps
